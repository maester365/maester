# Maester Tests

This folder contains the security checks that ship with Maester. From Maester 3.0 each check is a **native test**:
`Test.<ID>.ps1`, a PowerShell function with a `[MaesterTest(...)]` attribute, and `Test.<ID>.md`, its description
and remediation steps. The tests are part of the module: the build defines their functions in it, and
`Invoke-Maester` runs them from the module. You do not need a copy of this folder to run them.

The tests are organized into suites, each with a `suite.json` that sets its tags, default category and source:

- **Maester**: Tests built by the Maester team with contributions from the community. To learn more see
  [Maester Tests](https://maester.dev/docs/tests/maester).
- **cis**: Tests that verify the tenant's configuration conforms to the guidelines of the
  [Center for Internet Security (CIS) benchmark](https://www.cisecurity.org/benchmark/microsoft_365).
- **cisa**: Tests that verify the tenant's configuration conforms to the policies described in the Secure Cloud
  Business Applications ([SCuBA](https://cisa.gov/scuba)) Security Configuration Baseline
  [documents](https://github.com/cisagov/ScubaGear/blob/main/baselines/README.md).
- **EIDSCA**: Tests based on the [Entra ID Security Config Analyzer](https://maester.dev/docs/tests/eidsca/),
  generated by `build/eidsca/Update-EidscaTests.ps1`.
- **orca**: Tests based on the Office 365 Recommended Configuration Analyzer, generated by
  `build/orca/Update-OrcaTests.ps1`.
- **ad**: Active Directory tests. They run only after `Connect-Maester -Service ActiveDirectory`.
- **XSPM**: Exposure management tests.
- **Custom**: Not shipped. In a user's folder this is where their own tests go; see
  [Custom/README.md](./Custom/README.md).

## Running Maester

```powershell
Connect-Maester
Invoke-Maester
```

`Get-MtTest` lists every test and its metadata without connecting to a tenant. To learn more see
[maester.dev](https://maester.dev).

## Keeping your Maester tests up to date

The tests ship inside the module, so updating the module updates the tests:

```powershell
Update-Module Maester -Force
```

If you have copies of these tests from Maester 2.x (written by `Install-MaesterTests`), they are not run any more.
Remove them with `Update-MaesterTests -Path <folder>`. See
[Upgrading from 2.x](https://maester.dev/docs/upgrading-from-2x).

## Customizing tests

Change a test's severity, turn it off, or set its parameters in your `maester-config.json`, not by editing or
copying the test:

```json
{
  "TestSettings": [
    { "Id": "CIS.M365.1.1.1", "Severity": "High" },
    { "Id": "MT.1005", "Enabled": false, "Reason": "Covered by another control" },
    { "Id": "MT.1198", "Parameters": { "MaximumValidityDays": 180 } }
  ]
}
```

The severity levels are `Critical`, `High`, `Medium`, `Low` and `Info`. See the
[run configuration reference](https://maester.dev/docs/configuration/run-configuration).

## Contributing a test

New checks are native tests in the right suite folder. Scaffold one with `New-MtTest`, validate it with
`Get-MtTest -Path <file>`, run it with `Invoke-MtTest -Path <file>`, and follow
[Writing native tests](https://maester.dev/docs/writing-tests) and the
[contribution guide](https://maester.dev/docs/contributing). Built-in tests must not check their own connection
or licence, or wrap their body in a `try`/`catch` that only reports `-SkippedBecause Error`: they declare `Service`
and `CompatibleLicense`, and the engine does the rest. The unit tests in `powershell/tests` enforce this.

Pages under `website/docs/tests/` are generated from these files; do not edit them by hand.
