The default app management policy blocks custom, user-chosen secrets so that new application secrets are always generated by Microsoft Entra ID.

When a person picks the value of a client secret through the API, the result can be short, predictable or reused from elsewhere. Secrets that Microsoft Entra ID generates are long and random, so they cannot be guessed or sprayed.

The restriction only affects secrets that are added after it takes effect. Automation that supplies its own secret value must be changed to use the generated one.

#### Remediation action

1. Connect to Microsoft Graph with an account that has the Global Administrator role, or with the Security Administrator and Application Administrator roles.
2. Retrieve the current default app management policy before sending an update. Preserve all existing `passwordCredentials` entries under both `applicationRestrictions` and `servicePrincipalRestrictions` in the update. Sending only the new restriction can disable other active restrictions.
3. Set `isEnabled` to `true` and, under both `applicationRestrictions` and `servicePrincipalRestrictions`, add a `passwordCredentials` restriction of type `customPasswordAddition` with `state` set to `enabled` and `restrictForAppsCreatedAfterDateTime` set to a date before the oldest application in the tenant, such as the date the tenant was created. Applications created before that date are exempt, so a later date leaves existing applications out.
