# maester.dev

The Maester website: the home page, the docs, the test catalog, the command reference and the blog. It is built with
[Astro](https://astro.build) and [Starlight](https://starlight.astro.build), and shares its design tokens with
[maester.cloud](https://maester.cloud).

```shell
npm install
npm start          # http://localhost:4321
npm run build      # builds dist/, then checks that every old URL still resolves
```

Node.js 22.22 or later. The contributing guide has the details: [Contributing to Maester docs](https://maester.dev/docs/contributing#contributing-to-maester-docs-and-blog-posts).

## Where things are

| Path | What it is |
| --- | --- |
| `docs/` | The guides and the command reference (`docs/commands`, generated by `build/Update-CommandReference.ps1` and not kept in git). A file's path is its URL. |
| `blog/` | Blog posts, one folder each. |
| `versioned_docs/version-2.3.0/` | The Maester 2.x docs, frozen, served at `/docs/2.x` with `noindex`. |
| `scripts/prepare-data.mjs` | Generates what the site is built from and git doesn't keep, before `npm run dev` and `npm run build`: the test catalog, the command reference, the contributor credits and the sponsors. `npm run refresh-data` generates them again. |
| `scripts/og-images.mjs` | Renders each page's Open Graph card (`/og/<page>.jpg`) after `astro build`, from the card the page writes into `<meta name="maester:og">` (`src/lib/og.mjs`). Cards are cached by hash in `.cache/og`, so a build renders only the ones that changed. Raise `CARD_VERSION` in `src/lib/og.mjs` after changing the design. |
| `scripts/make-icons.mjs` | Writes the manifest icons and `apple-touch-icon.png` from `src/assets/maester-mark.svg`. Run it by hand when the mark changes. `public/favicon.ico` is the old site's favicon, kept as it is. |
| `src/data/test-catalog.json` | Every built-in test, exported from the test source (not kept in git). The test pages and the catalog are built from it at build time by `scripts/generate-test-docs.mjs` (into the ignored `.generated/`). |
| `src/data/versions.json` | The release each test, command and parameter first shipped in. With `version-config.js` it decides what is marked **Preview**. |
| `src/data/url-contract.txt` | Every URL the site had before the move to Astro. The build fails if one stops resolving. |
| `src/lib/redirects.mjs` | Writes `dist/_redirects` (Cloudflare Pages) for the URLs that moved. |
| `src/lib/content-loader.ts` | Loads the guides, tests, 2.x archive and blog into Starlight with the URLs they had on Docusaurus. |
| `src/components/` | Starlight overrides (`overrides/`), the version picker, the test catalog, the explainer player and the other components. |
| `src/pages/` | The pages outside the docs: home, sponsor, contributors, manifesto, test builder, EIDSCA sync. |
| `public/explainers/` | The HyperFrames explainers: HTML and GSAP, played live by `<Explainer>`. |

## Deployment

The build-website workflow (`.github/workflows/build-website.yaml`) builds the site on every push to `main`, once a
day and on request, then uploads `website/dist` to the Cloudflare Pages project with wrangler. The build needs
PowerShell and the maester-bot token, which Cloudflare's own build doesn't have, so the Pages project must not also
build from git. Pull requests are built as a check and never deployed. Pages serves `docs/intro.html` at `/docs/intro` and redirects `/docs/intro/` there, so
every URL has one form, without a trailing slash.
