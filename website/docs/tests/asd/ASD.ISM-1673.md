# ASD.ISM-1673 - Microsoft Office macros are blocked from making Win32 API calls.

<div className="test-byline"><div className="test-byline-avatars"><a className="test-byline-avatar test-byline-avatar--author" href="/contributors/jusso-dev" title="jusso-dev · Original author"><img src="https://github.com/jusso-dev.png" alt="jusso-dev" /></a></div><div className="test-byline-meta"><span className="test-byline-text">Contributed by <a href="/contributors/jusso-dev">jusso-dev</a></span><a className="test-byline-link" href="/contributors">All contributors →</a></div></div>

## Overview

Microsoft Office macros are blocked from making Win32 API calls (ISM-1673, Essential Eight Maturity Level Two, Restrict Microsoft Office macros).

Macro malware calls the Win32 API to allocate memory, load shellcode and reach the operating system directly. Blocking those calls leaves VBA its document automation and takes away its use as a loader. This check reads the attack surface reduction rules of every Intune Windows configuration policy (Endpoint security and settings catalog policies share the same setting definitions) and passes when an assigned policy sets **Block Win32 API calls from Office macros** to **Block**. Audit and Warn only report the behaviour and do not satisfy the control.

#### Remediation action

1. In **Microsoft Intune admin center**, go to **Endpoint security** > **[Attack surface reduction](https://intune.microsoft.com/#view/Microsoft_Intune_Workflows/SecurityManagementMenu/~/asr)** and open your attack surface reduction rules policy, or create one for **Windows** with the profile **Attack Surface Reduction Rules**.
2. Set **Block Win32 API calls from Office macros** to **Block**. Pilot the rule in **Audit** first if Office add-ins or line-of-business macros are in use.
3. Assign the policy to all workstations.
