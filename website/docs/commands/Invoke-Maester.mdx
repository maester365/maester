## SYNOPSIS

This is the main Maester command that runs the tests and generates a report of the results.

## SYNTAX

```powershell
Invoke-Maester [[-Path] <String>] [-Tag <String[]>] [-ExcludeTag <String[]>] [-Product <String[]>]
 [-Feature <String[]>] [-Area <String[]>] [-Severity <String[]>] [-Suite <String[]>] [-IncludeLongRunning]
 [-IncludePreview] [-OutputHtmlFile <String>] [-IncludeAffectedObjects] [-RedactUserIdentity <String>]
 [-OutputMarkdownFile <String>] [-OutputMarkdownSummaryFile <String>] [-OutputJsonFile <String>]
 [-OutputFolder <String>] [-OutputFolderFileName <String>] [-PesterConfiguration <Object>]
 [-Verbosity <String>] [-NonInteractive] [-PassThru] [-MailRecipient <String[]>] [-MailTestResultsUri <String>]
 [-MailUserId <String>] [-TeamId <String>] [-TeamChannelId <String>] [-TeamChannelWebhookUri <String>]
 [-SkipGraphConnect] [-DisableTelemetry] [-SkipVersionCheck] [-ExportCsv] [-ExportExcel] [-NoLogo]
 [-OutputMode <String>] [-DriftRoot <String>] [-TestId <String[]>] [-ExcludeTestId <String[]>]
 [-Config <Object>] [-DryRun] [-SkipBuiltIn] [-ProgressAction <ActionPreference>] [<CommonParameters>]
```

## DESCRIPTION

Using Invoke-Maester is the easiest way to run the Pester tests and generate a report of the results.

For more advanced configuration, you can directly use the Pester module and the Get-MtHtmlReport function.

By default, Invoke-Maester runs the tests that ship with Maester and the custom tests in the current directory and all subdirectories recursively, except Active Directory tests, preview tests and long-running tests.
Active Directory tests run only after an explicit Connect-Maester -Service ActiveDirectory call succeeds.

-Product, -Feature, -Area, -Severity and -Suite select tests by their typed attributes.
Each takes a list: the values of one selector are alternatives, and different selectors must all match.
They combine the same way with -Tag and -TestId.
The tags of Maester 2.x, such as CA or CIS, still select the same built-in tests.

## EXAMPLES

### EXAMPLE 1

```powershell
Invoke-Maester
```

Runs the built-in tests and the custom tests under the current folder (except for Active Directory tests, preview tests and long-running tests) and generates a report of the results in the ./test-results folder.

### EXAMPLE 2

```powershell
Invoke-Maester ./maester
```

Runs the built-in tests and the custom tests and maester-config.json in the folder ./maester (except for Active Directory tests, preview tests and long-running tests) and generates a report of the results in the default ./test-results folder.

### EXAMPLE 3

```powershell
Invoke-Maester -Tag 'CA' -IncludeLongRunning
```

Runs the tests with the tag "CA" and includes long-running tests.
Generates a report of the results in the default ./test-results folder.

### EXAMPLE 4

```powershell
Invoke-Maester -Tag 'CA', 'App' -IncludePreview
```

Runs the tests with the tags 'CA' and 'App' and includes preview tests.
Generates a report of the results in the default ./test-results folder.

### EXAMPLE 5

```powershell
Invoke-Maester -Product entra -Severity Critical, High
```

Runs the Entra ID tests whose severity is Critical or High.
Values of one selector are alternatives; different selectors must all match.

### EXAMPLE 6

```powershell
Invoke-Maester -Suite cisa -Area authentication
```

Runs the tests of the CISA suite that are about authentication.
-Product, -Feature, -Area, -Severity and -Suite select by the typed attributes of the tests and combine with -Tag and -TestId.

### EXAMPLE 7

```powershell
Invoke-Maester -OutputFolder './my-test-results'
```

Runs tests and generates a report of the results in the ./my-test-results folder.

### EXAMPLE 8

```powershell
Invoke-Maester -OutputHtmlFile './test-results/TestResults.html'
```

Runs the tests and generates a report of the results in the specified file.

### EXAMPLE 9

```powershell
Invoke-Maester -Path ./tests/EIDSCA
```

Runs tests in the EIDSCA folder.

### EXAMPLE 10

```powershell
Invoke-Maester -MailRecipient john@contoso.com
```

Runs the tests and sends a report of the results to an email recipient.

### EXAMPLE 11

```powershell
Invoke-Maester -TeamId '00000000-0000-0000-0000-000000000000' -TeamChannelId '19%3A00000000000000000000000000000000%40thread.tacv2'
```

Runs the tests and posts a summary of the results to a Teams channel.

### EXAMPLE 12

```powershell
Invoke-Maester -TeamChannelWebhookUri 'https://some-url.logic.azure.com/workflows/invoke?api-version=2016-06-01'
```

Runs the tests and posts a summary of the results to a Teams channel.

### EXAMPLE 13

```powershell
Invoke-Maester -Verbosity Normal
```

Shows results of tests as they are run, including details on failed tests.

### EXAMPLE 14

```powershell
$configuration = New-PesterConfiguration
$configuration.Run.Path = './tests/Maester'
$configuration.Filter.Tag = 'CA'
$configuration.Filter.ExcludeTag = 'App'

Invoke-Maester -PesterConfiguration $configuration
```

Runs Pester tests in the ./tests/Maester folder that include the 'CA' tag and exclude the 'App' tag.

### EXAMPLE 15

```powershell
Connect-Maester -Service All
Invoke-Maester -IncludeLongRunning -IncludePreview
```

Connect to all Microsoft 365 services and run their tests, including the long-running and preview tests.
Active Directory tests remain excluded.

### EXAMPLE 16

```powershell
Connect-Maester -Service ActiveDirectory
Invoke-Maester -Product ad -SkipGraphConnect
```

Explicitly connect to Active Directory, then run the Active Directory tests without requiring a Microsoft Graph connection.

### EXAMPLE 17

```powershell
Invoke-Maester -TestId 'MT.1005', 'CISA.MS.AAD.3.*'
```

Runs only test MT.1005 and the tests whose ID starts with CISA.MS.AAD.3.
A test named by its exact ID runs even if it is a preview or long-running test.

### EXAMPLE 18

```powershell
Invoke-Maester -ExcludeTestId 'MT.1024.*' -DryRun -PassThru
```

Shows what would run, and why every other test would not, without running any test.
Each test that would have run is reported as NotRun with reason DryRun.
Native tests are only read; Pester-format custom tests still go through Pester discovery, which runs their BeforeDiscovery and Describe-level code.

### EXAMPLE 19

```powershell
Invoke-Maester -Config ./maester-config.json, @{ Selection = @{ DefaultAction = 'Skip' }; TestSettings = @(@{ Id = 'MT.1005'; Enabled = $true }) }
```

Runs with an explicit configuration instead of the config files found next to the tests.
Several sources are merged left to right; here only tests enabled in TestSettings are run.

### -OutputMode

How the console output is written.
Interactive draws a live status line with the result counts, a progress bar and the running test, on a terminal.
Stream writes lines only, for CI and redirected output, with a progress line every 50 tests or 10 seconds and log groups and annotations on GitHub Actions and Azure Pipelines.
Plain is Stream without colour or symbols.
Auto, the default, picks Interactive on a terminal and Stream otherwise.
The MAESTER_OUTPUT_MODE environment variable and Output.ConsoleMode in maester-config.json set it too.
