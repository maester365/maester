Background (from the session that started this one):
Maester is a PowerShell framework that checks Microsoft 365 security configuration. The defender's path (design accepted 5 November 2026, docs/proposals/defenders-path.md) orders fixes the way Microsoft Learn documents: what must be in place first, what a fix unlocks, and whether the tenant is ready. Readiness checks cover prerequisites that are tenant states rather than settings. They report a count and a share and pass above a threshold, so the action plan can say whether a fix like "require compliant devices" would lock users out.

Milestone M1 (draft PR maester365/maester#2683, branch feat/defenders-path) shipped the Step attribute and the catalogue, where these two steps are marked Unchecked until checks exist. Learn says devices only need to be registered in Entra and enrolled in Intune to be marked compliant, not joined, which is why the device check measures compliance among devices that sign in.
