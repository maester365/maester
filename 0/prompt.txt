Background (from the session that started this one):
Maester is a PowerShell framework that checks Microsoft 365 security configuration. The defender's path (design accepted 5 November 2026, docs/proposals/defenders-path.md) orders fixes the way Microsoft Learn documents. Its catalogue (powershell/assets/steps) holds steps, their relationships and cited sources. Each source has a Learn Url with no locale, a Mirror repo name, a Note in Maester's own words and a Reviewed date.

The owner's Learn mirrors (built with merill/learn-mirror) crawl Learn four times a day and make one commit per changed page. That makes git history a free change feed: a cited page that changed after its Reviewed date needs a maintainer to re-read it.

Milestone M1 (draft PR maester365/maester#2683, branch feat/defenders-path) shipped the format, the loader (Get-MtStepCatalog) and its checks. Owner rulings: proposals are for review only, the workflow keeps a weekly issue and never opens PRs, and the catalogue keeps our own wording, never copied text.

Task:
Build milestone M6 of the defender's path: the tooling that keeps the step catalogue current. It's described in section 13 of `docs/proposals/defenders-path.md`.

Read first: section 13, the catalogue format in section 4 (especially 4.5, Sources), `powershell/assets/steps/` and `powershell/internal/engine/Get-MtStepCatalog.ps1`. Then read how `merill/learn-mirror` lays out its files (its README and one mirror repo): file paths, the front matter fields `source_path`, `original_content_git_url` and `ms.topic`, and `.learn-mirror/state.json`.

Build in `build/steps/`, PowerShell 7.4+, one function or script per file with comment-based help, following `AGENTS.md`:
1. `Update-MtLearnMirror.ps1`: clones or updates the nine public mirrors (`merill/entra-docs-mirror`, `intune-docs-mirror`, `defender-docs-mirror`, `security-docs-mirror`, `purview-docs-mirror`, `teams-docs-mirror`, `sharepoint-docs-mirror`, `exchange-docs-mirror`, `windows-server-docs-mirror`) into a cache folder that git ignores. It writes a URL-to-file index, and follows Learn's redirects for old URLs. Today 23 of the 77 Intune and Defender links in check guides are redirects, so resolve them with HTTP HEAD and cache the answers.
2. `Find-MtStepCandidate.ps1`: for the Learn pages that check guides (`tests/**/Test.*.md`) and catalogue `Sources` link, pulls prerequisite sections and sentences ("Prerequisites", "before you", "first", "must", "won't work without", "requires") with their mirror file and line. It writes proposals as JSON for a maintainer to review. Optional model rewording, if you add it, is behind a switch and off by default. Nothing writes to the catalogue.
3. `Test-MtStepSource.ps1`: for each catalogue source with a `Url`, finds its mirror file and lists the mirror commits to that file since `Reviewed`. It exits non-zero when any changed.
4. `.github/workflows/step-sources.yaml`: weekly plus manual. It runs `Test-MtStepSource.ps1` and keeps one open issue that lists the steps whose sources changed, with a diff link for each. It updates the issue rather than opening new ones, needs least-privilege `permissions`, and never opens pull requests.
5. Unit tests with no network calls, in `powershell/tests/general/`: use a small fixture git repository built in TestDrive for `Test-MtStepSource.ps1`, and fixture Markdown for the extraction.

Don't edit `powershell/assets/steps/` or the design doc. Another session owns them. If the format needs a field the tooling depends on, report it instead.
